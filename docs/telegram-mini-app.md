# Telegram Mini App для редактирования памяти

Дизайн-документ. Зафиксирован по итогам обсуждения 2026-10-01. Реализация — отдельным шагом.

## Понимание задачи

- Сейчас `/pantry` и `/profile` — read-only рендер памяти из SQLite, а любая правка (статус продукта, вкусы, ограничения, техника, servings/cooking_time) идёт только через переписку с LLM-агентом (`agent/chef.py`) — медленно для рутинных структурных изменений.
- Цель Mini App — быстрое редактирование структурированных данных: тап вместо диалога с агентом.
- Аудитория — `approved`-пользователи бота (небольшая закрытая группа, одобрение админом), не публичный сайт.
- Фронтенд — TypeScript + Vue.
- Scope v1: **Pantry** (`pantry_items`), **Профиль** (`profile_tags`: likes/dislikes/restrictions/equipment), **Настройки** (`servings`, `cooking_time` из `profiles`).
- Вне v1: история блюд (`history`) — визуальный обзор оценок не нужен, остаётся в чате.
- `/pantry` и `/profile` как текстовые команды остаются работать параллельно (не убираются сразу) — при реализации покрыть `TODO`-комментариями на будущее удаление, когда Mini App обкатается.
- Онбординг (заполнение анкеты с нуля при первом `/start`) этим дизайном не затрагивается и не дублируется — Mini App только про правку уже существующих данных.

## Допущения

1. Небольшая нагрузка (десятки пользователей одновременно) — не проектируем под масштаб.
2. Mini App работает только внутри Telegram; авторизация — через валидацию Telegram `initData`, отдельной системы логина нет.
3. Mini App пишет напрямую в те же таблицы SQLite, что и бот (`memory/store.py`) — без отдельной синхронизации данных.
4. Интерфейс на русском.
5. Нужен новый тонкий HTTP-слой (FastAPI/aiohttp) поверх существующих функций `memory/store.py` для обслуживания фронтенда — сам API (эндпоинты, схема запросов) в этот документ не входит, только факт, что он нужен (см. «Вне рамок»).

## Decision Log

| Решение | Альтернативы | Почему |
|---|---|---|
| Фронтенд — TypeScript + Vue | React, Svelte | Ближе пользователю как фронтендеру |
| Навигация — хаб (карточки разделов) + нативный `Telegram.WebApp.BackButton` | Нижний tab bar; одна страница с аккордеоном | У Telegram Mini App нет нативного нижнего таб-бара — пришлось бы верстать свой, конфликтующий по месту с системным UI; `BackButton` сделан ровно под push/pop-навигацию хаб→раздел. Аккордеон плохо масштабируется для длинного списка Pantry |
| Вход — постоянная Menu Button у поля ввода | Inline-кнопки под `/pantry`, `/profile` | Доступ в любой момент, независимо от контекста диалога |
| `/pantry`, `/profile` остаются как текстовые команды, с `TODO` на удаление в будущем | Убрать сразу при вводе Mini App | Не резать существующий флоу до того, как Mini App обкатан |
| Тема — light/dark через `Telegram.WebApp.themeParams` как CSS-переменные, обновление по `themeChanged` | Ориентироваться на системную тему ОС | Синхронизировано именно с темой клиента Telegram пользователя, а не ОС |
| Автосохранение без общей кнопки «Сохранить»/`MainButton` на экранах Pantry/Профиль/Настройки — каждый тап сразу пишет в БД | Форма с явным батчевым сохранением | Это и есть «быстрое редактирование» — цель всего Mini App |
| Фидбек сохранения: при успехе — тихая инлайн-микроанимация на элементе + haptic; при ошибке — неисчезающий снекбар с «Повторить» | Тост на каждое изменение независимо от исхода | Успех не должен прерывать; провал обязан быть заметным, иначе изменение теряется незаметно |
| Undo только для удаления (тег, товар Pantry): swipe + снекбар «Удалено · Отменить» (Gmail-паттерн) | Modal confirm-диалог перед удалением | Не прерывает диалогом, даёт тот же защитный эффект; для toggle-действий (чекбокс, добавление тега) undo не нужен — отмена тривиальна повторным тапом |
| Pantry: список сгруппирован по статусу low → out → have | Алфавитный список вперемешку | То, что требует внимания, — наверху |
| Pantry: смена статуса — тап по цветному чипу по кругу (have→low→out→have) | Dropdown/отдельный экран редактирования | Одно касание вместо нескольких шагов |
| Pantry: добавление товара — bottom sheet поверх списка | Отдельный экран | Не прерывает контекст списка |
| Profile: equipment — объединённый чеклист (захардкоженный частый список ∪ уже сохранённые кастомные пункты пользователя из `profile_tags`), «+ своё» добавляет пункт и не закрывает форму | Отдельное поле «своё» текстом, не связанное с чеклистом | Кастомный пункт становится неотличим от дефолтного при следующем открытии — та же таблица, без спецслучаев; повторный ввод без закрытия формы позволяет добавить несколько пунктов подряд |
| Profile: likes/dislikes/restrictions — открытый тег-инпут; equipment — чеклист | Единая механика для всех kind | likes/dislikes/restrictions — открытый словарь, equipment — по сути закрытый список |
| Settings: servings — степпер (±); cooking_time — segmented control с пресетами (15/30/60/не важно) | Свободный числовой/текстовый ввод | Соответствует грубой точности, с которой поля реально использует агент при подборе рецепта; быстрее тапается |

## Финальный дизайн

### Общая структура

- Vue Router: `/` (хаб), `/pantry`, `/profile`, `/settings`.
- Цвета — только из `Telegram.WebApp.themeParams` (`bg_color`, `text_color`, `hint_color`, `button_color`, `secondary_bg_color`) как CSS-переменные; пересчитываются на событие `themeChanged`.
- Высота layout — по `viewportStableHeight`, не `100vh` (скачет при открытии клавиатуры/разной высоте клиента).
- `BackButton`: скрыт на хабе, показан внутри любого раздела → возвращает на хаб.
- `MainButton`: скрыт везде, кроме формы добавления нового товара в Pantry (там — «Добавить», активна только когда заполнено название).

### Хаб (`/`)

Три карточки вертикальным стеком: Pantry / Профиль / Настройки. Каждая — иконка + название + живая подпись с текущим состоянием (например «2 товара заканчиваются» у Pantry, «5 вкусов, 2 ограничения» у Профиля, текущие значения у Настроек) — подгружается одним лёгким запросом при открытии хаба.

### Pantry (`/pantry`)

- Секции по статусу в порядке low → out → have; в карточке товара — название, количество (если есть), срок годности (подсветка, если истекает в пределах `EXPIRY_WARNING_DAYS`).
- Статус — тап по цветному чипу, по кругу have→low→out→have, сразу `PATCH` + оптимистичное обновление + инлайн-фидбек.
- Добавление — bottom sheet («+» над списком): название (обязательно), количество/срок годности (опционально).
- Удаление — свайп влево → снекбар «Удалено · Отменить» (4–5 сек).
- Пустое состояние — подсказка «Добавь первый товар» с той же кнопкой «+», а не пустой экран.
- Тач-цели (чипы, карточки) — не меньше 44×44px.

### Профиль (`/profile`)

- Четыре группы: restrictions, equipment, likes, dislikes (ограничения и техника выше — чаще влияют на то, что можно готовить).
- likes/dislikes/restrictions — чипы с тег-инпутом (ввод текста → Enter добавляет чип, крестик на чипе удаляет).
- equipment — чеклист (захардкоженный частый список ∪ существующие кастомные `profile_tags`), тап переключает есть/нет; «+ своё» добавляет новый пункт в тот же чеклист без закрытия формы.
- Автосохранение на каждый тап, как в Pantry; удаление тега — тот же паттерн swipe + undo-снекбар.
- Пустая группа — не скрывается, а показывает «Пока ничего не добавлено» с фокусом на поле ввода/чеклисте.

### Настройки (`/settings`)

- `servings` — степпер (`−` / значение / `+`), диапазон 1–8.
- `cooking_time` — segmented control: 15 мин / 30 мин / 60 мин / Не важно.
- Автосохранение на каждый тап, без undo (тривиально обратимо повторным тапом).

## Вне рамок этого дизайна

- История блюд (`history`) — визуальный обзор оценок, экран в Mini App.
- HTTP API слой (эндпоинты, схема запросов/ответов, валидация `initData`) — отдельный backend-дизайн.
- Деплой, HTTPS, хостинг фронтенда.
- Полное удаление текстовых команд `/pantry`, `/profile` — когда Mini App обкатается.
